Attach to terminal — options

While a user is watching the live CLI (inline in the session card, or in the fullscreen overlay), give them a prominent, unmistakable way to attach to that same session in their own terminal and take the keyboard.

Hover/click the controls below — copy buttons, popovers, banners and dismiss buttons are live so you can feel each interaction.

Today the attach command lives only in a collapsed “Continue in your terminal” disclosure under the card — easy to miss. The command is tmux attach -t vc_3f7a9c21. Every idea below surfaces exactly that, but more visibly and always-while-watching. Each is shown on a faithful replica of the real live view.

A. Attach pill in the live header bar inline + fullscreen
Add a “⌨ Attach” pill right into the header bar that already carries Minimize / Fullscreen. It sits next to the title, always visible the whole time you’re watching. Clicking it drops a small popover with the exact command + copy. Zero new chrome, lives where your eyes already are.
Live CLI
$ claude --resume ● Reading src/app/page.tsx ● Editing component layout… └ applied 3 edits
Take the keyboard
You’re watching read-only. Paste this in your terminal to attach to this exact tmux session and type directly.
tmux attach -t vc_3f7a9c21

Best for: discoverability with no layout change. Trade-off: the bar gets one more control; on narrow cards it competes for space.

B. Persistent command strip under the terminal recommended inline + fullscreen
A slim accent-tinted footer welded to the bottom of the terminal: a “⌨ Type in your own terminal” lead, the full command inline, and a copy button. Always visible, never collapsed, reads like a status bar. The command itself is the hero — no extra click to reveal it.
Live CLI
$ claude --resume ● Running tests… └ 42 passed
⌨ Type in your terminal tmux attach -t vc_3f7a9c21

Best for: maximum clarity — the command is right there, one copy away, every second you watch. Trade-off: permanently spends ~36px of vertical space.

C. Floating “take control” chip over the terminal inline + fullscreen
A floating accent chip pinned to the corner of the terminal (same family as the existing scroll buttons), hovering over the output. Click to pop a compact card with the command + copy + a one-line “what this does”. Costs no layout space; dismisses out of the way.
Live CLI
$ claude --resume ● Searching the codebase… ● Found 7 matches in 4 files └ summarizing
Attach in your terminal
Jump into this live session and type directly. The browser view stays read-only.
tmux attach -t vc_3f7a9c21

Best for: keeping the option visible without spending layout. Trade-off: overlays a sliver of terminal output; floating UI can feel less “solid” than a bar.

D. Read-only callout banner at the top of the view inline + fullscreen
A one-line banner just under the header that names the situation — you’re watching, read-only — and makes attaching the call to action. It teaches why you’d attach (you can’t type here) and offers the command right in the sentence. Dismissible so it doesn’t nag on repeat views.

Best for: explaining the read-only limitation and converting it into the attach action. Trade-off: banners read as “alerts”; once dismissed the option is gone for that view.

E. Split dual primary actions — Watch live and Attach card action row
Promote “Attach” to a first-class peer of “Watch live” in the card’s action row, instead of hiding it in a disclosure. Two side-by-side accent buttons: watch here, or take it into your terminal. Visible before and during watching, so the choice is framed up front.
Session card · action row

Best for: making the terminal path obviously equal to the in-browser path. Trade-off: doesn’t live inside the live view itself; pair with A/B/C for in-view presence while watching.

F. Prominent action in the fullscreen header fullscreen
For the fullscreen overlay specifically, place a solid “⌨ Attach in your terminal” button in the modal header next to Close — the natural spot for a primary action at this size. Clicking reveals the command inline. Ensures the option is loud in the immersive mode, not just the small inline box.

Take the keyboard
Attach to this tmux session in your own terminal to type directly.

Best for: the fullscreen mode, where there’s room for a bold header action. Trade-off: fullscreen-only; needs an inline counterpart (A/B/C) to cover the embedded view.

G. “Read-only” badge in the header that expands to attach inline + fullscreen
Replace the plain “Live CLI” title with a clickable Read-only badge. It states the constraint at a glance, and clicking it expands the attach command — tying the affordance directly to the reason a user would reach for it. Quiet until you want it.

You can watch here, but typing happens in the terminal. Attach to take the keyboard:

Best for: communicating read-only-ness and the fix in one control. Trade-off: replaces the title; the attach command is one click away rather than always shown.

Tip: these aren’t mutually exclusive — a common pairing is B (always-visible strip in the inline box) + F (bold header action in fullscreen), or A used in both modes for one consistent control. Tell me which direction you like and I’ll wire it into the real components.
